데이터 전처리: 결측치·이상치·인코딩·스케일링

데이터 다루기 · 읽는 시간 약 10분

대부분의 머신러닝 모델은 숫자로 된, 빈칸 없는 표만 입력으로 받습니다. 현실의 데이터는 그렇지 않습니다. 전처리는 현실의 데이터를 모델이 먹을 수 있는 형태로 바꾸는 작업이며, 여기서의 선택이 성능을 크게 좌우합니다.

목차
  1. 결측치 처리
  2. 이상치 처리
  3. 범주형 변수 인코딩
  4. 스케일링
  5. 가장 흔한 실수: 데이터 누수

결측치 처리

빈 값을 다루는 방법은 크게 "지우기"와 "채우기"입니다.

지우기

df = df.dropna(subset=["price"])     # 타깃이 빈 행은 학습에 쓸 수 없으므로 삭제
df = df.drop(columns=["memo"])        # 대부분이 빈 열은 열째로 삭제

결측이 적고 무작위로 발생했다면 삭제가 가장 간단합니다. 하지만 결측이 특정 조건에서 몰려 생긴다면(예: 고가 차량만 주행거리 미기재) 삭제하는 순간 데이터가 한쪽으로 치우칩니다.

채우기

방법적합한 경우
평균분포가 대칭이고 이상치가 적은 숫자형
중앙값한쪽으로 치우쳤거나 이상치가 있는 숫자형 (가격, 소득 등)
최빈값범주형
새 범주 "Unknown"범주형에서 결측 자체가 의미 있을 때
그룹별 대표값같은 차종의 중앙값처럼 더 비슷한 집단의 값으로 채울 수 있을 때
 
from sklearn.impute import SimpleImputer

num_imputer = SimpleImputer(strategy="median")
X_train[["mileage"]] = num_imputer.fit_transform(X_train[["mileage"]])
X_test[["mileage"]]  = num_imputer.transform(X_test[["mileage"]])   # 학습 데이터의 중앙값을 그대로 사용

마지막 줄에서 테스트 데이터에는 fit 없이 transform만 쓴 점에 주목하세요. 이유는 데이터 누수에서 설명합니다.

이상치 처리

이상치에는 두 종류가 있습니다. 하나는 오류(키 1,700cm), 다른 하나는 드물지만 실제인 값(슈퍼카 가격)입니다. 오류는 고치거나 지우고, 실제 값은 함부로 지우지 않는 것이 원칙입니다.

IQR 규칙으로 찾기

사분위수 범위(IQR = Q3 − Q1)를 이용해, Q1 − 1.5×IQR보다 작거나 Q3 + 1.5×IQR보다 큰 값을 이상치 후보로 봅니다.

q1, q3 = df["price"].quantile([0.25, 0.75])
iqr = q3 - q1
low, high = q1 - 1.5 * iqr, q3 + 1.5 * iqr
outliers = df[(df["price"] < low) | (df["price"] > high)]
print(len(outliers))

대응 방법

  • 제거: 명백한 입력 오류일 때.
  • 상·하한으로 자르기(클리핑): 극단값의 영향만 줄이고 싶을 때. df["price"].clip(low, high)
  • 로그 변환: 오른쪽 꼬리가 긴 분포를 완만하게 만들 때.
  • 그대로 두기: 트리 기반 모델(의사결정나무, 랜덤포레스트)은 이상치에 비교적 둔감합니다.

범주형 변수 인코딩

"가솔린", "디젤", "전기" 같은 문자열은 모델이 계산할 수 없으므로 숫자로 바꿔야 합니다.

원-핫 인코딩 (One-Hot Encoding)

범주마다 열을 하나씩 만들고 해당하면 1, 아니면 0을 넣습니다. 범주 사이에 순서가 없을 때 기본 선택입니다.

fuelfuel_가솔린fuel_디젤fuel_전기
가솔린100
전기001
 
from sklearn.preprocessing import OneHotEncoder
enc = OneHotEncoder(handle_unknown="ignore")   # 테스트에 처음 보는 범주가 나와도 오류 없이 처리

순서형 인코딩 (Ordinal Encoding)

"소형 < 중형 < 대형"처럼 순서가 있으면 0, 1, 2로 바꿀 수 있습니다. 순서가 없는 범주에 이 방법을 쓰면 모델이 "전기(2)는 가솔린(0)의 두 배"처럼 엉뚱한 관계를 배울 수 있으니 주의하세요.

범주가 수백 개라면? — 원-핫 인코딩은 열이 폭발적으로 늘어납니다. 빈도가 낮은 범주를 "기타"로 묶거나, 트리 모델에서는 순서형 인코딩을 써도 괜찮은 경우가 많습니다.

스케일링

주행거리는 수만 단위, 연식은 2000~2026 사이입니다. 거리 계산이나 경사하강법을 쓰는 모델(KNN, SVM, 신경망, 규제가 있는 선형회귀)은 값의 크기가 큰 특성에 휘둘리기 때문에 단위를 맞춰야 합니다.

방법변환특징
표준화 (StandardScaler)(x − 평균) / 표준편차평균 0, 표준편차 1. 가장 무난한 기본값
정규화 (MinMaxScaler)(x − 최솟값) / (최댓값 − 최솟값)0~1 범위. 이상치에 민감
RobustScaler(x − 중앙값) / IQR이상치가 많을 때

트리 기반 모델은 값의 대소 비교만 하므로 스케일링이 필요 없습니다.

가장 흔한 실수: 데이터 누수

전처리에서 가장 많이 하는 실수는 전체 데이터로 평균·중앙값·스케일을 계산한 뒤 학습용과 테스트용으로 나누는 것입니다. 이렇게 하면 테스트 데이터의 정보가 학습 과정에 새어 들어가, 평가 점수가 실제보다 좋게 나옵니다. 이를 데이터 누수(data leakage)라고 합니다.

올바른 순서는 다음과 같습니다.

  1. 먼저 학습용·테스트용으로 나눈다.
  2. 학습용 데이터로만 fit해서 평균, 중앙값, 범주 목록 등을 구한다.
  3. 그 값으로 학습용과 테스트용 모두를 transform한다.

타깃 정보가 특성에 섞여 들어가는 경우도 누수입니다. 예를 들어 "대출 연체 여부"를 예측하는데 "연체 후 독촉 횟수"를 특성으로 쓰면, 예측 시점에는 알 수 없는 정보를 쓰는 셈입니다.

파이프라인으로 묶기

scikit-learn의 Pipeline과 ColumnTransformer를 쓰면 위 순서를 자동으로 지킬 수 있어 누수 실수를 원천적으로 막아 줍니다.

from sklearn.compose import ColumnTransformer
from sklearn.pipeline import Pipeline
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.linear_model import Ridge

num_cols = ["year", "mileage"]
cat_cols = ["fuel", "brand"]

preprocess = ColumnTransformer([
    ("num", Pipeline([("impute", SimpleImputer(strategy="median")),
                      ("scale", StandardScaler())]), num_cols),
    ("cat", Pipeline([("impute", SimpleImputer(strategy="most_frequent")),
                      ("onehot", OneHotEncoder(handle_unknown="ignore"))]), cat_cols),
])

model = Pipeline([("prep", preprocess), ("reg", Ridge(alpha=1.0))])
model.fit(X_train, y_train)          # 전처리의 fit도 학습 데이터에서만 일어남
print(model.score(X_test, y_test))

이 구조는 교차검증을 할 때도 그대로 쓸 수 있어서, 폴드마다 전처리가 올바르게 다시 계산됩니다.
